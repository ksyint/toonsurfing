- 9개 원본 기본 브랜치의 트리 해시가 `import/2026-10-22` 태그 아래 대응 경로와 일치합니다.
- 원본 기본 브랜치, 프런트엔드 개발 브랜치와 PR을 포함한 12개 참조의 커밋을 검증했습니다.
- 기본 브랜치 커밋이 통합 이력의 조상으로 연결되어 있고 서브모듈이 없습니다.
- 원본 파일·브랜치 정보는 `sources.json`, 소스별 파일·정의·의존성 목록은 `source-inventory.json`에 보관했습니다.

## 정적 검사와 웹 빌드

- `make check`: 원본 트리·참조, 모든 추적 Python 구문과 JSON, 심볼릭 링크 대상, 전체 도달 가능한 이력의 알려진 인증정보 패턴 검사를 통과했습니다.
- `git diff --check` 및 실행 스크립트의 `bash -n` 검사를 통과했습니다.
- Node.js 18.19.1 / npm 9.2.0에서 원본 잠금 파일을 사용해 의존성을 설치했습니다.
- `CI=true npm run build --prefix apps/web`가 성공했습니다. 최종 빌드는 ESLint 경고가 없습니다. 기존 CRA/Browserslist 도구의 안내 메시지는 남아 있습니다.

## 컷 추출

통합 코드와 변경하지 않은 원본 코드를 같은 Python 3.12 환경에서 각각 실행했습니다. 포함된 `girls-trial` 3개 회차에서 생성한 **JPEG 223개가 파일명과 바이트 단위로 일치**했습니다. 생성한 이미지가 정상 JPEG이며 기본 높이 제한을 충족하는지도 확인했습니다.

원본 저장소의 미리 생성된 `result/`와 현재 기본 인자의 결과 파일 수는 다릅니다. 통합 전후 실행 결과를 직접 비교하여 코드 이동으로 인한 차이가 없음을 확인했습니다.

## API 설치와 HTTP

별도 Python 3.10.20 환경 `.venv-api`에 `requirements/api.txt`를 설치했습니다. HTTP 검증에는 PyTorch 2.5.1 CPU, Gradio 4.44.1, clip-retrieval 2.45.0을 사용했습니다. `api.lock`은 Python 3.10 기준으로 별도 해석한 고정 버전 명세입니다.

`scripts/smoke_api.py`는 외부 모델 허브를 오프라인으로 설정하고 OpenAI 키 없이 실제 서버를 임시 포트에서 실행하여 다음을 확인했습니다.

- `/health`의 JSON 응답
- OpenAPI의 세 검색 경로 등록
- `/images`에서 반환한 JPEG와 저장 파일의 바이트 일치
- Gradio 화면과 설정, 공개 검색 함수 이름
- 필수 입력이 없는 검색 요청의 HTTP 422 응답
- 검증 종료 후 서버 프로세스 종료

API 경로 설정과 공통 Pic2Word 심볼릭 링크도 확인했습니다. 실제 OpenAI 호출, 외부 번역, CLIP/LaBSE 검색 품질, CUDA Pic2Word 추론, KoLLaVA 추론 및 모델 학습은 실행하지 않았습니다.
